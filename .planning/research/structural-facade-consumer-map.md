## Scope and notation

This map covers the normal historical upload path, direct sample-intelligence path, persistence/transport, product APIs, Results, Finding Review, Investigation, Evidence Record, frontend fallbacks, and tests. It does not classify connector-result durability or change any P0.1 code.

- `T/P/X/C/F/I` mean telemetry-derived / persisted with the completed upload / learned across real runs / customer-visible through an authenticated product response or UI / formal-finding influence / Investigation-or-Evidence influence.
- `Y`, `N`, and `mixed` are literal answers for those six required properties.
- “Persisted” refers to historical-upload JSON persistence. The whole `sii_intelligence` object survives because `project_result_for_transport` omits other large artifacts but not `sii_intelligence` (`backend/app/services/upload_persistence.py:12-46`).
- “Customer-visible” includes raw authenticated product API responses even when no current React component renders the field.
- Each row has exactly one primary classification from the campaign vocabulary.

## Default authority and serialization trace

```text
historical upload
  -> upload_pipeline.run_upload_pipeline
  -> evaluate_sii exactly once through run_upload_analysis_compatibility
  -> compatibility baseline/engine result/attribution
  -> build_upload_intelligence
       -> evidence guard + customer result/evidence fields
       -> build_structural_cognition (eager facade)
       -> spread all facade keys into sii_intelligence
       -> replace qualified structural_explanation[0] with facade explanation summary
  -> upload_pipeline overwrites sii_intelligence.replay_timeline with upload replay
  -> upload_jobs places sii_intelligence in result
  -> analysis_result/finding reconstruction (facade does not classify findings)
  -> scoped upload-result JSON + transport projection + evidence record/product UI
```

## Consumer-map conclusion

The default upload authority can be separated without modifying SII mathematics or qualified finding semantics by removing the eager facade call/spread, preserving the explicit non-facade allowlist above, and handling the three mixed/ambiguous seams deliberately: `structural_explanation`, review-window terminology, and facade lineage/cognition-state APIs. The final upload replay is a fourth high-risk seam by name only: it is a separate telemetry replay that overwrites the facade replay and must remain.
